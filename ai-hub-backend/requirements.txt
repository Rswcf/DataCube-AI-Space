# (captured from the CI closure on Python 3.11, the interpreter Railway uses).
#
# Why pins: this file used to say `fastapi>=0.109.0` and nothing else, so every
# CI run and every `railway up` installed whatever was newest that day. On
# 2026-09-18 that silently meant starlette 1.6.0 — a major bump — where the
# local venv still had 0.50, and framework behaviour differed between the two:
# tests that passed locally failed in CI, and one pre-existing test had been
# asserting nothing in CI for some time. Pinning makes an upgrade a decision
# someone makes, not something a build does.
#
# To upgrade: relax the pin(s) you mean to move, let CI resolve, run the
# backend suites, and paste the new versions back here.
